# Plan 5.14 — 单据体支持(EntryEntity + TabPage + TabControl)

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` to implement this plan task-by-task. Tasks use checkbox (`- [ ]`) syntax.

**Goal:** 让 agent 能在 BOS 扩展上自建单据体(EntryEntity)、自建页签(TabPage / TabControl),并在单据体上加字段;同时支持 entry / tab 的删除和重命名。覆盖客户实施 80% 单据体场景(新增明细行 / 重构 tab 布局),并为 v0.2 自建表单铺路。

**Architecture:** 沿用现有 BOS RPC 路径(`SaveForIDEV9`)— 不引入新写入端点,所有"新建/删除/改名"都通过 baseline-diff DCXML 表达,服务端自动比对应用。具体改动:

1. `fkernel-parsers.ts` 扩展元素识别(EntryEntity / TabPageAppearance / TabControlAppearance / EntryEntityAppearance 的子元素提取)
2. `existing-elements.ts` read-merge 增加 entries / tabs(baseline-diff 累积要求)
3. `dcxml.ts` emitter 新增 4 类元素的渲染分支
4. 字段渲染识别 entry container → emit `<EntityKey>` 子元素 + 跳过 Container/Top/Left
5. `connector.ts` 加 `getNextSequenceInt32(category)`(创建 entry 时唯一新增 RPC 调用)
6. 新增 9 个 agent 工具:`create_tab_control` / `create_tab_page` / `create_entry` + `delete_*` ×3 + `rename_*` ×3

Delete / rename 实现路径统一:在 read-merge 的 raw chunks 上做**过滤**(delete)或**正则替换 Name/Caption**(rename),无需 action 标记 — BOS 服务端比对 baseline-diff 自动 cascade。

**Tech Stack:** TypeScript / Vitest(沿用 Plan 5.x 栈,无新增)

**Wire format 实证依据:** memory `bos_entry_creation_wire_format.md`(2026-04-29 抓包,#1334/#1357/#1384/#1405/#1425/#1445/#1465/#1485)

**Scope 红线(本 plan 不做):**
- ❌ SubEntryEntity(嵌套子单据体)— 留 v0.2
- ❌ 自建 Form(从零造单据,非给原厂加扩展)— 留 v0.3
- ❌ Head 侧 TabControl 创建(`FSPLITECONTAINER~Panel1`)— 客户实施 99% 在 entry 侧;v0.2 视需求扩
- ❌ entry 移到另一个 TabPage(只能删了重建)
- ❌ entry 字段重排(Tabindex 由工具内部连续递增,不暴露给用户)
- ❌ TabControl 重命名时调整 TabPage 数量(只改 caption,不增减 page)

## Wire format 速查表

每个新元素的最小子元素集(实证抓自 BOS Designer #1334 等):

### EntryEntity(单据体定义)

```xml
<EntryEntity ElementType="35" ElementStyle="0">
  <EntryName>UNW_Cust_Entry100002</EntryName>            <!-- <DevCode>_Cust_Entry<int> -->
  <EntryPkFieldName>FEntryID</EntryPkFieldName>           <!-- 固定 -->
  <Seq>14</Seq>                                            <!-- parent.entries + ext.entries + 1 -->
  <TableName>UNW_t_Cust_Entry100002</TableName>            <!-- <DevCode>_t_Cust_Entry<int> -->
  <GroupColumnInfo>
    <GroupColumnInfo>
      <Id>052ad82f-0940-45d8-bd80-827eb9e7bc03</Id>        <!-- 新 dashed-GUID -->
    </GroupColumnInfo>
  </GroupColumnInfo>
  <Name>测试体</Name>                                       <!-- 用户传 zh-CN -->
  <Id>0144d058...</Id>                                     <!-- 新 32-hex compact GUID -->
  <Key>F_UNW_Entity_rnk</Key>                              <!-- F_<DevCode>_Entity_<3 char lc> -->
</EntryEntity>
```

### EntryEntityAppearance

```xml
<EntryEntityAppearance ElementType="35" ElementStyle="1">
  <Caption>测试体</Caption>                                 <!-- = EntryEntity.Name 同步 -->
  <PageRows>100</PageRows>                                 <!-- 固定 -->
  <Dock>5</Dock>                                            <!-- 固定 = Fill -->
  <Container>FTAB1_UNW_P_O9W</Container>                   <!-- parentTabPage.Key -->
  <Left>336</Left><Top>90</Top><Height>65</Height><Width>300</Width>
  <Id>...</Id><Key>F_UNW_Entity_rnk</Key>                  <!-- = EntryEntity.Key -->
</EntryEntityAppearance>
```

### TabControlAppearance(整个控件)

```xml
<TabControlAppearance ElementType="1005" ElementStyle="1">
  <Container>FSPLITECONTAINER~Panel2</Container>           <!-- entry 侧固定 -->
  <Caption>页签控件</Caption>                                <!-- 默认,可改 -->
  <Id>...</Id>
  <Key>F_UNW_Tab_8mg</Key>                                 <!-- F_<DevCode>_Tab_<3 char lc> -->
</TabControlAppearance>
```

### TabPageAppearance(单页)— 两种用法

```xml
<!-- 用法 A:挂在原厂 FTab1 下(单 page) -->
<TabPageAppearance ElementType="1004" ElementStyle="1">
  <Container>FTab1</Container>
  <Caption>页签</Caption>
  <Id>...</Id>
  <Key>FTab1_UNW_P_o9w</Key>                                <!-- FTab1_<DevCode>_P_<3 char lc> -->
</TabPageAppearance>

<!-- 用法 B:挂在自建 TabControl 下(创建 TabControl 时默认 3 个) -->
<TabPageAppearance ElementType="1004" ElementStyle="1">
  <Container>F_UNW_Tab_8mg</Container>                      <!-- = TabControl.Key -->
  <Caption>页签</Caption>
  <Id>...</Id>
  <Key>F_UNW_Tab_8mg_P0_8mg</Key>                           <!-- <TabControlKey>_P<idx>_<TabControl 3 char> -->
</TabPageAppearance>
```

### Entry-field(字段挂在 entry 上)— 与 head field 差异

```xml
<TextField ElementType="1" ElementStyle="0">
  <ConditionType>0</ConditionType>
  <PropertyName>F_UNW_Text_vjj</PropertyName>
  <EntityKey>F_UNW_Entity_rnk</EntityKey>                   <!-- ★ 新增,放 PropertyName 后 -->
  <FieldName>F_UNW_TEXT_VJJ</FieldName>
  <ListTabIndex>9005</ListTabIndex>                        <!-- 全局递增,沿用 head 逻辑 -->
  <Name>测试备注</Name>
  <Id>...</Id><Key>F_UNW_Text_vjj</Key>
</TextField>

<TextFieldAppearance ElementType="1" ElementStyle="1">
  <EmptyText action="setnull" />
  <Key>F_UNW_Text_vjj</Key>
  <ListDefaultWidth>100</ListDefaultWidth>
  <EntityKey>F_UNW_Entity_rnk</EntityKey>                   <!-- ★ 新增 -->
  <Tabindex>1</Tabindex>                                   <!-- ★ 每 entry 独立从 1 起递增 -->
  <LabelWidth>100</LabelWidth><Width>150</Width>           <!-- 默认 150(head 是 280) -->
  <Visible>1023</Visible><VisibleExt>100</VisibleExt>
  <Caption>测试备注</Caption><Id>...</Id>
  <!-- ★ 不发 <Container> / <Top> / <Left>:网格列由 EntryEntityAppearance 定位 -->
</TextFieldAppearance>
```

### Delete / rename:无 action 标记

- **Delete:从 DCXML 中移除该元素**(连带级联清理 entry-fields / TabControl 下的 TabPages)
- **Rename:仅改 `<Name>` 和 / 或 `<Caption>` 子元素值**,元素位置 / 其他子元素不变

服务端比对 baseline-diff 自动应用。

## 工具矩阵

| 工具 | 输入 | 输出 | 内部行为 |
|---|---|---|---|
| `kingdee_create_tab_control` | extId, caption?, tabPageCount?(默认 3) | tabControlKey, tabPageKeys[] | 生成 Key 模板 + 3 个子 TabPage,挂在 `FSPLITECONTAINER~Panel2` |
| `kingdee_create_tab_page` | extId, parentTabControlKey?(默认原厂 `FTab1`), caption? | tabPageKey | 生成单 TabPage 挂指定 TabControl |
| `kingdee_create_entry` | extId, name, parentTabPageKey | entryKey, tableName, entryName, seq | 调 `GetSequenceInt32("t_BOS_CustEntry", 1)` → 命名模板 + Seq 计算 + 自动建 EntryEntity + EntryEntityAppearance |
| `kingdee_add_fields`(改造) | extId, fields[]({type,key,caption,container,...}) | (现有结构) | 识别 container 是 tab 还是 entry → entry 走"emit EntityKey + 跳过 Container/Top/Left + Tabindex 每 entry 内递增"分支 |
| `kingdee_delete_entry` | extId, entryKey | ok | read-merge 过滤 EntryEntity + EntryEntityAppearance + 所有 EntityKey=该 entry 的 fields/appearances |
| `kingdee_delete_tab_page` | extId, tabPageKey | ok | 检查无 entry 挂着否则拒绝 → 过滤 TabPageAppearance |
| `kingdee_delete_tab_control` | extId, tabControlKey | ok | 检查所有子 page 无 entry 挂着否则拒绝 → 过滤 TabControl + 所有子 TabPages |
| `kingdee_rename_entry` | extId, entryKey, newName | ok | 同步改 EntryEntity.Name + EntryEntityAppearance.Caption |
| `kingdee_rename_tab_page` | extId, tabPageKey, newCaption | ok | 改 TabPageAppearance.Caption |
| `kingdee_rename_tab_control` | extId, tabControlKey, newCaption | ok | 改 TabControlAppearance.Caption |

## Self-Review

**实证依赖**:整套 wire format 来自 2026-04-29 抓包(memory `bos_entry_creation_wire_format.md`),涵盖创建 / rename / delete entry+tab+control 的完整 cycle。Tabindex 算法 / 命名模板 / GetSequenceInt32 调用 / cascade 行为均已 byte-level 实证。

**风险点**:
1. **Tabindex / Seq 并发性**:工具内部基于 read-merge 算下一个 max+1。如果用户同时跑两个 agent 操作(理论场景),可能撞。**v0.1 不防护**(单工具内部串行 + agent loop 串行已经够),v0.2 视需求加锁。
2. **TabControl/TabPage 命名后缀重复**:实证 BOS Designer 在 TabPage Key 后缀**复用 TabControl 后缀**(不独立 random)。我们工具 `create_tab_control` 也照此实现;`create_tab_page` 单独建时则独立 random。
3. **Caption 同步**:实证 BOS Designer rename entry 不同步 Caption(只改 Name)— 我们工具显式同步,不再问用户(否则要双输入),实施场景不会有人故意要 Name 和 Caption 不一致。
4. **Container 重命名 v0.1 不暴露**:即使工具支持改 caption,parent / container 关系不变。如果用户想把 entry 移到另一个 TabPage,**v0.1 只能删了重建**(scope 红线)。

**回滚策略**:每个 Phase 独立 commit,可单独 revert。Phase 0(基础设施)是其他 Phase 的硬依赖,不可单独 revert;Phase 1-6 之间相对独立。

**测试覆盖**:每个 Phase 加单测(target 90%+ branch coverage on新代码),Phase 7 加端到端 smoke + 用户实测。
