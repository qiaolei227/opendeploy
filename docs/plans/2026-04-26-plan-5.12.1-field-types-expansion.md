# Plan 5.12.1 — 字段类型扩展

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` to implement this plan task-by-task. Tasks use checkbox (`- [ ]`) syntax.

**Goal:** 把 `kingdee_add_field` 从仅 `type='text'` 扩展到 11 普通 type + 6 个 BaseDataField 子类 + BasePropertyField + ReferencePropertyField，加配套 `kingdee_describe_basedata` 反查工具，让 agent 能加客户实施 80% 场景的字段。

**Architecture:** 沿用 Plan 5.9 三层架构 — tool（`bos-write-tools.ts`）→ writer（`bos-writer.ts:addFieldToExtension`）→ XML 渲染（`bos-xml.ts`）。每层按 type 分支：tool 层 enum + 参数校验，writer 层 type → spec 映射，XML 层 `insertFieldIntoKernelXml(type, spec)` 按 type 生成对应 C# 类的 XML 节点。新增 `kingdee_describe_basedata` 工具走 `T_META_OBJECTTYPE` + relevant 元数据表反查基础资料的 schema。

**Tech Stack:** TypeScript / mssql / Vitest（沿用 Plan 5.x 栈，无新增）

**Scope 红线（本 plan 不做）：**
- 不做 `entityKey` 参数（留 5.12.2 实体 sub-plan 处理 — 涉及 `<EntryEntity>` 节点定位逻辑，与 entity 工具紧耦合）
- 不做字段验证（FieldValidationElement — 留独立 sub-plan）
- 不做字段计算 / 业务规则（留 5.12.3）
- 不做字段精细布局（top/left 仍保留默认 10/10 + 暴露可选参数，不做容器内自动排布）
- 不做"修改已有字段"或"删字段"工具（v0.2+，本 plan 只加）

## Type 矩阵参考

| type 字符串 | C# 类 | XML 标签 | 必需参数（除 key/caption 外）| 可选 |
|---|---|---|---|---|
| `text` | TextField | `<TextField>` | — | maxLength |
| `large_text` | LargeRichTextField | `<LargeRichTextField>` | — | — |
| `int` | IntegerField | `<IntegerField>` | — | min / max |
| `decimal` | DecimalField | `<DecimalField>` | — | precision / min / max |
| `amount` | AmountField | `<AmountField>` | — | precision / currencyField |
| `qty` | QtyField | `<QtyField>` | — | precision / unitField |
| `date` | DateTimeField (date-only mode) | `<DateTimeField>` | — | — |
| `datetime` | DateTimeField | `<DateTimeField>` | — | — |
| `checkbox` | CheckBoxField *or* CheckBox flavor of TextField | `<CheckBoxField>` 待实证 | — | — |
| `combo` | ComboField | `<ComboField>` | `comboItems: [{value, caption}]` | — |
| `mul_combo` | MulComboField | `<MulComboField>` | `comboItems: [{value, caption}]` | — |
| `base_data` | BaseDataField (含 6 子类映射) | `<BaseDataField>` | `refBaseDataObjectKey` | refBaseDataKindKey / displayMemberFieldName |
| `base_property` | BasePropertyField | `<BasePropertyField>` | `sourceField` + `srcDisplayFieldName` | — |
| `reference_property` | ReferencePropertyField | `<ReferencePropertyField>` | `sourceField` | — |
| `color` | ColorField | `<ColorField>` | — | — |
| `mobile` | MobileField | `<MobileField>` | — | — |

**BaseDataField 6 子类映射**（`refBaseDataObjectKey` 决定）：
- `BD_MATERIAL` → 物料
- `BD_Customer` → 客户
- `BD_Supplier` → 供应商
- `BD_Department` → 部门
- `BD_Empinfo` → 职员
- `SEC_User` → 用户
- 其他 K3 内置基础资料 → 自动适配（agent 通过 describe_basedata 查到的 key 都可用）

> **实证级别**: `text` 已生产; 其他 type 的 XML 节点形态在 5.12.1 实施期会从 `Kingdee.BOS.Core.dll` 反编译产物 + 客户 dev 环境 SAL_SaleOrder 实测XML 双重确认。`checkbox` 的 BOS 类对应方式（独立 CheckBoxField vs TextField 子类）需先实证再实现 — 实证不通就退到"勾选下拉" 用 ComboField + 是/否两选项替代。
